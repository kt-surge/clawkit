# 文件任务来源与进度检查点（CM-E4修复）

## 需求与失败依据

2026-10-05第二轮完整任务6/6均未满足质量门禁。候选配置有36次实际主任务响应和2次压力压缩，17/25文件正确，prod字段缺失或套用错误规则；动态任务44次主任务响应后预算停止，输出仍为旧状态。公开规则与Gold经独立转写核对一致。不能仅靠保留用户约束或摘要中存在关键词证明任务正确，也不能用根状态COMPLETED替代业务评分。

## 技术参考

[Pi官方压缩文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)将目标、约束、进度、决定和后续步骤写入结构化摘要，并累计readFiles/modifiedFiles。[Anthropic上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)讨论压缩和独立任务笔记，用于长期任务续接。采用文件来源导航与确定性进度的思路，自行实现；不复制代码，不引入依赖或额外摘要调用。

## 本轮实现合同

1. 普通ReAct每次run创建独立轨迹，只消费实际ToolExecutionResult。工具名/调用ID必须匹配且元数据来自可信内置工具；read仅在SUCCESS且只读时记录返回文本摘要、最后读取轮次和原生路径。摘要是实际返回文本的SHA256，不是全文件哈希，也不证明完整或新鲜。
2. write/edit仅在SUCCESS且EFFECT_CONFIRMED时记录文件写入；VERIFICATION_PENDING、拒绝、失败、未知、部分效果不记为完成。写入确认不等于业务正确或任务完成。已有未知结果警告仍生效。
3. 来源最多32条、写入最多256条，重复路径更新，超出范围淘汰旧条目。只保存路径/工具/轮次/返回摘要、调用ID的SHA256和有界统计；调用ID摘要仅用于内部匹配，不进入模型导航。不保存原文内容、用户权限或模型推测的任务结论。JSON转义路径，拒绝过长/控制字符路径，输出包含遗漏计数。
4. 原始预算进入预警、会话含Conversation Summary，或压缩后的上下文已缺少本run最新原生read的完整返回时，注入单条[Runtime]导航提示。可见性必须同时匹配TOOL角色、实际调用ID摘要与实际返回文本摘要；用户/摘要/模型复述、旧调用或占位符均不能替代。首次后置触发前保留第一遍压缩的审计与结果，再从已压缩Session通过唯一ContextPipeline重建，最多增加一遍预算/压缩；任一遍失败均停止主任务模型调用。每轮替换，全部新增提示开销进入普通输入预算。字符上限为min(4096,max(768,窗口/4))；全部导航开销进入输入账本。优先来源，随后写入路径。缺失精确值时重读原文；状态会变化时读取最新来源，必要时更新已写文件。导航不会给予审批权限或自动认定版本变化。
5. 提示仅持续本run，finally清理；不持久化到Session或长期Memory。PLAN_EXECUTE与跨会话里程碑暂未接入。不能把这部分称为完整持久化检查点系统或正则里程碑。
6. 输出截断仍最多2次恢复，拒绝响应的部分工具不执行，用量保留。恢复提示允许每响应最多两个短工具调用，避免单工具建议扩大往返次数；不改输出上限、HTTP重试、共享预算、授权范围。该提示是建议，并非工具计数硬门禁。

## 验证与验收

离线验证实际成功/失败状态、路径更新、输出有界与不携带原文、普通引擎压缩后重新读取并写入、下一run不泄漏；保留既有上下文/可靠性合同。固定响应仅证明机制。整仓clean verify、零网络完整任务prepare与封存audit通过后，按逐轮合同申请新的6实例回归授权；实际要求仍为业务正确、20+原生主任务响应和真实压力压缩同时满足，不填充轮次、不放宽评分或预算。已有v1留出已观察，新泛化结论需另设未观察任务。

## 第三轮发现的原生覆盖拒绝分类修复

第三轮159请求/1262668 total Token，候选两项仍失败。候选动态第15轮原生write因缺少overwrite=true在任何写入前拒绝，却由旧适配层归类为结果未知，随后修正被sticky目标锁阻断，进入重复读取。原始失败封存于tmp/cm-full-live-20261005-03/，没有重写评分。

WriteTool的结构化入口现在先执行自己拥有的路径/现存非空文件/显式覆盖检查。只在该前置分支直接返回OVERWRITE_REQUIRED与LOCAL_ERROR_NO_EFFECT/NO_EFFECT_CONFIRMED；不启动旧执行入口，也不创建目录/临时文件。其他路径继续普通执行，任何执行期错误保留保守语义，不根据错误代码或文本归类为无副作用。默认不覆盖、显式覆盖、路径边界、确定性文件验证保持有效。已有未知attempt不会被此修复自动释放。

离线回归覆盖写前拒绝、不变字节、显式覆盖、执行期同名错误仍未知，以及普通引擎“写入→覆盖拒绝→显式修正→独立文件验证”4次主模型固定响应和3次工具调用；目标attempt分别为VERIFIED_SUCCESS/FAILED_NO_EFFECT/VERIFIED_SUCCESS。固定响应仅验证机制，模型效果待新授权实测。成对读取循环检测缺口和prod空值规则误用继续作为后续需求，不宣称本修复已解决全部任务。


## 第四轮复核与来源丢失触发修复

第四轮6实例全部尝试、0完整通过，155请求/1251018 total Token。写前覆盖拒绝分类在摘要基线配置的2次真实拒绝中生效，随后均完成验证更新；全轮无目标锁阻断。它不代表候选任务质量改善，候选配置17/25、动态8/21。业务值为null和动作规则误用继续开放。

候选动态最新revision 3原文进入第27–29轮，第30轮L2将其变为26字符占位符，检查点没有启用。预算报告为OK，而压缩决策还计入锚点、输出预留及余量，因此两者并非同一触发条件。执行过L2不等于满足冻结的压力口径：本实例没有同时满足beforeStatus为WARN及以上且成功缩减Token的L2/L3，原压力计数0与评分保持不变。不能描述为L1遮蔽或从未执行L2。

针对性离线回归使用真实DefaultContextPipeline、原生read/write和与完整任务相同的2048输出预留。原始预算OK时实际触发L2并遮蔽来源，旧实现因缺少导航先失败；修复后在下一模型请求前生成导航，经管线核对完整提示成本，再读取更新来源、写入文件并独立验证，下一run及clearSession均无提示泄漏。调用ID与返回摘要精确匹配、同路径新调用和有界淘汰亦已覆盖；10项针对性回归通过。首个夹具未满足预算OK条件的失败与真正复现缺导航的失败均单独保留，不把前者当作产品修复依据。

该轨迹只保存32条最新读取的有界元数据，不保存或自动恢复原文、不自动发起read，也不判断业务语义或当前文件是否已变化。固定响应证明机制，不证明真实模型会选择重读或正确应用新状态。整仓clean verify和新prepare/audit后，下一次实际效果验证仍需独立逐轮授权；旧数据、Gold、评分、预算与原版Context保持冻结。


## 第五轮后的任务说明原文保留合同

第五轮候选动态首次满足完整门禁；候选配置仍有8个遥测回退错误，并将指定汇总写到另一路径。导航只保留来源元数据，不能替代精确规则。原文重读后部分错误仍持续，因此本改进只保证有界可用性，不承诺语义正确或效果提升。

范围仅为候选Context的消息保留策略：从最近一条USER消息提取明确文件路径，仅选取其后已完成read工具交换中至多2个路径的最新返回；每个被选返回最多4096字符，所在完整交换的其他返回也随原调用链保留、计入总界，不代表额外来源获选或文件当前新鲜。所有保留交换连同原调用参数/其他返回/角色与ID等估算字符开销合计最多8192字符。完整ASSISTANT→TOOL交换原样保留，避免断开协议；越界、占位符、空值或不完整图不固定，沿用普通压缩与来源导航。用户未引用的文件继续常规处理。路径只做词法匹配，不推断符号链接、绝对/相对别名或实际文件新鲜度。

L2掩码、T3驱逐和L3摘要均遵守同一保留集合；原始TOOL/ASSISTANT角色、调用ID和内容不变，不复制到SYSTEM，不将工具文字提升为权限或已确认事实。保留成本按实际消息进入唯一ContextPipeline、模型输出预留和硬预算；无法容纳仍失败关闭。最近USER改变后不延用先前任务的固定集合，原会话历史仍按既有Session合同保存。该机制不另存原文档案，不改变FileTaskCheckpoint的元数据边界。

同时修正正则路径提取：完整保留末段含扩展名的相对文件路径及显式./或../路径，避免仅留下/migration-summary.json等后缀；URL和URI不得拆出伪文件路径，也不将glob/grep、静态/SSR这类斜线枚举识别为相对文件。无扩展名且无./或../前缀的相对目录、未含分隔符的裸文件名不自动推断。路径提取不等于识别里程碑或理解条件规则。离线回归须覆盖完整规则与精确产物路径、最新read替换、来源/消息角色、数量/内容/交换总界、任务切换、L3和硬预算。评分/Gold/环境验证器/任务/总预算/原版Context冻结保持不变，真实效果待单独授权。

技术取舍：继续参考Pi结构化约束与Anthropic强调的精确上下文选择；本项目采用有界原工具交换保留，自行实现，不新增模型调用或依赖，不从公开规则计算答案。


原版对照的ConstraintExtractor现也从原版41份源码编译的私有JAR加载；候选相对路径策略不能经父加载器污染原版。只为这个实现类放行源码差异，构造器/公共方法ABI仍与原版一致，其他未审阅公共类型变化继续拒绝。单独记录原版提取器字节码摘要；原版manifest和JAR均不修改。离线反射回归直接确认两组对同一句相对路径输入分别得到旧后缀与新完整路径。


## 单次任务验收与显式来源可见性

第七轮区分了两类问题：生产环境 domain 在摘要中遗漏后被推断错；动态动作在首次压力压缩前、完整规则与最新证据均可见时已误判。仅增强收尾提示不足以保证正确完成。

来源导航现在为每条 read 标记 PRESENT/MISSING，依据当前模型上下文的 TOOL 调用 ID 与返回文本摘要共同判断；缺失条目优先展示，但仍受原字符界限制。PRESENT 只说明那次历史返回仍可见，文件可能已经变化；MISSING 仅说明该原始 TOOL 文本当前不可见，不代表任务未完成，也不要求逐条清空。需要精确值或新鲜证据时才重读；不会自动缓存、回填或派发读取。最新原生失败读取撤销旧引用。可见性变化经过唯一 ContextPipeline 的有界重建与预算；再次变化则 SOURCE_VISIBILITY_UNSTABLE 终止主任务派发。

参考 [smolagents 的调用方收尾校验](https://huggingface.co/docs/smolagents/main/guided_tour#customizing-agent-termination-conditions)，普通 ReAct 增加可选单次入口：

```java
engine.run(prompt, RunToolScope.ALL, request ->
    applicationValidator.checkCurrentOutputs(request.proposedOutput(), request.control()));
```

applicationValidator 由可信应用自行实现，只执行有界本地只读检查，不调用模型、写文件或读取评测 Gold；运行时不理解领域规则，也不沙箱化这个回调。TaskCompletionCheck.Result 提供 accept、retry(code, feedback)、reject(code, feedback)。调用方可检查完整性、最新版本关联、规则条件和业务字段，但验收只覆盖其声明条件。反馈有2048字符上限，码有64字符界，异常不泄露原始错误文本。

已配置时，普通无工具结束与工具 COMPLETE 均先验收；最多允许2次纠正续接。纠正进入原 ReAct、ContextPipeline、权限、安全、副作用和取消/deadline/Token/请求/工具预算。拒绝、异常、空结果或耗尽纠正次数不记 COMPLETED。验收提示是本run的临时数据，结束移除，下一run不继承。旧入口默认 NONE，PLAN_EXECUTE 不支持该入口且明确拒绝，不能默默绕过。声明为只读的回调由可信调用方负责实现；它不是从任意自然语言自动生成的正确性证明。

离线示例通过实际文件操作展示两种纠正：根据原始profile域名修正输出；现场revision变化后重新读取并按应用声明的冷却/授权顺序更新动作。固定模型响应仅验证机制。既有v1评测默认入口尚未装配业务验收回调，公开结构验证器、Gold、任务和评分不改；不能将旧任务prepare的成功当作这项验收的模型效果，或直接宣称CLI所有任务已经有业务验收。


### 公开工作流程的显式接入

两个自建长任务另设 acceptance-v2 修订，显式装配调用方检查；旧v1与CLI默认不启用。验收内部按已审阅公开规则和当前实际源字节判等，反馈只含错误位置/规则/来源，不给正确值。三组共用同一检查，独立评分与原生采证新鲜度仍由封存审核核对。具体适用范围、版本、边界和授权见 [真实长任务合同第6节](context-memory-live-full-plan.md#6-公开规则验收修订-v2离线交付真实效果待验证)。本修订改变程序辅助条件，不是单独的Context算法收益。


## 公开验收 v2 后第一批重复读取提示

公开验收 v2 首轮候选配置的 25/25 产物正确，但最后一次写入后仍有 7 次读取请求，耗用 69175 total Token，最终未提交完成验收。读取包含多个文件组轮换，并非连续相同批次；本修复不声称完整覆盖这条轨迹。候选动态仍有最新修订未传播完的产物，不能跳过新鲜采证或独立业务验收。

普通 ReAct 每个 run 增加有界的原生只读批次观察：至少两个工具调用，调用 ID、工具名、可信 BUILTIN 元数据与实际结果匹配，全部 SUCCESS 且 NO_EFFECT_CONFIRMED 时才参与。参数对象按键排序，数组顺序保留；比较工具名、参数、实际返回文本 SHA256 和截断标记，批次顺序与调用 ID 的改变不影响等价判断。连续三批完全相同才提示一次；变化、失败、未知、写操作、远程工具、单调用或不完整结果重置计数。内部只保存批次摘要、计数和待提示标志，不缓存返回内容，不持久化。

提示先进入普通 ContextPipeline，输入成本和硬额度检查照常生效；下一轮移除，finally 清理，下一 run 与 clearSession 不继承。它让模型核对未完成条件并提交已完成工作，不阻断工具、自动标记完成或决定新鲜度。需要轮询或最新验证时仍可读取。原单工具循环检测保留；多个不同批次轮换的循环尚未覆盖。

离线回归通过实际双文件读取触发提示，再提出缺少产物的完成请求；应用验收仍拒绝，后续新鲜读取、写入与独立验收可继续。另覆盖返回变化、来源不可信、失败/未知、混合写入、重复 ID 与结果缺失。固定响应只证明机制，未证明模型减少读取、任务完成率提高或 Token 节省。三个评测组共用本运行时修订，不能归因候选压缩算法。

低余额停止经源码与既有合同复核，来自评测入口的保守请求预留，不是输出已正确的完成判断。本轮不调整预留、单实例/整轮 Token、请求或纠正上限；新输入收缩策略和动态修订传播仍待单独离线方案。旧数据、Gold、评分器、环境推进与原版 Context 不改；不追加真实模型调用。


## 2026-10-06：多组轮换读取与低余额输入规划

第二批将只读观察扩展为有界读取阶段：连续成功的原生多调用批次达到6批，且最新批次与最近12个请求组中的一次参数及返回摘要一致时，也提示一次。原连续3批提示保留，每段读取阶段只提示一次；相同参数组返回变化、写入、失败、未知或不合格结果清空整段记录，单次 run 外不保留。只保存两种批次 SHA256 和有界计数，组的淘汰不作为任务结论。它覆盖上一轮“6个不同组后回到先前组”的观察模式，不强制完成或禁止必要重读，也不能仅凭提示断言冗余读取已消失。

定向回归先复现未提示，再验证轮换组提示、变化撤销、12组淘汰和写入重置。原真实文件完成验收回归保留；本批没有模型响应的新证据，不报告读取节省。三组共用此运行时，不能归因候选 Context。
