# CM-E4 独立真实长任务合同

> 2026-10-05。独立于24任务/216实例的历史重放。此文定义两种自建本地工作流程；离线合同、固定响应、预检均不产生真实20+Turn证据。默认prepare不读取 API 密钥、不创建网络Provider，也不代表调用授权。

## 1. 历史与保护单位

每个实例只有一个初始任务请求，生产 AgentEngine 从空会话开始。禁止加载已写好的用户/助手/工具历史，禁止将正确答案或目标步骤写进 Session、Working Memory 或模型摘要。后续历史由真实模型请求、实际文件工具和本地环境反馈形成；任务结束后不追加聊天，不按分数补轮次。

2026-10-05 的无网络回归复现：仅按 USER 发言划分保护区时，单个请求的24次完整工具往返始终属于同一轮，压缩失败为 COMPACT_HARD_LIMIT。候选改为按完整 assistant/tool 往返识别近期交换，并单独原样保护最近3条 USER 请求；并行工具的全部结果留在同一组。未完成或重复ID的工具图不被部分驱逐。普通引擎固定响应回归25个 TurnStarted已完成，但它没有真实模型用量，不能关闭本合同门禁。

原版 Context 仍使用封存源码，公共类型保持一致。三个主对照共用 Engine、Provider、工具、任务与全部阶段预算。C1 在单请求场景使用滚动摘要＋最近3个完整工具交换，原始用户请求单独保留；不能把一个包含全部工具历史的 USER 轮当成“摘要强基线”。此分组口径与正式重放中的最近3个 USER 轮不同，结果不混在一起统计。

## 2. 两个实际本地流程

### 配置迁移

对一个隔离的多服务配置项目生成 v2 预览：8个服务、3个环境，共24份配置。涉及上游连接、超时与重试、资源与副本、日志脱敏、TLS、追踪和发布策略，按公开迁移规则处理环境覆盖。原始文件和生产配置保持不变；只写预览。独立程序检查全部转换值、跨服务关系、约束和汇总，不以文件SHA或模型自述“完成”代替迁移正确。

### 证据变化后的任务续接

对10个合成目标生成证据记录与处置预览。工作区快照由本地环境程序推进，共3个 revision：首次有效预览后变化一次，第二版全部预览齐全后再次变化。环境只依据公开结构规则和实际写入推进，不能读取评分 gold 或替模型纠正处置选择。每次变化可重新读取当前状态；最终输出须使用最后一次观察，已完成的历史处置记录保持原样，不实际重启、清理、伸缩或访问服务器。

两个任务都不是生产事故或真实用户项目。文件操作与环境变化实际发生，模型/工具历史真实形成；外部状态仍是自建合成环境。没有人工制造的“等待20轮”步骤。

## 3. 参数与授权草案

预定2任务×3组×1次=6实例：C1_ROLLING_SUMMARY、C2_FROZEN_ORIGINAL_CONTEXT、C3_CANDIDATE_CONTEXT。每实例重新创建空 HOME、工作区和运行目录，按任务轮换先后组别。

受控窗口16384 Token、每请求最多2048输出、temperature=0、reasoning关闭、零传输重试、cl100k_base。较216重放轮的4096窗口/1024输出更大，用于完整配置工具载荷；不称供应商原生容量，也不据此宣称重放与长任务可直接横比。最近3个完整工具交换、完整初始请求和SYSTEM保护内容必须能装入预算，无法装入时如实失败。

预算草案：每实例最多60请求/360000 total Token/160次工具提议/900秒；整轮360请求/2160000 total Token/3600秒。摘要、主任务、独立验证及所有失败共享额度。必须先完成执行器、离线预检、整仓验证和独立审计，再单独请求本轮范围及预算授权；不能复用18开发实例或216正式重放的剩余额度。

## 4. 评分与门禁

分别报告任务输出、行为约束、模型实际main轮数、压缩层级与次数、所有失败、实际各阶段input/output/total/cache，以及完整任务耗时。

真实main轮数用根任务TurnStarted交叉核对根任务REACT的实际响应与usage；压缩摘要、Session/Memory摄入、子任务、独立验证和发送前拒绝不能增加该数。没有ACTUAL usage的固定响应仅作机制测试。不得用副作用工具的文件hash验证自证业务输出正确。

每个实例记录“质量满足”“至少20个真实main轮”“压力压缩发生”三个条件。候选两个任务均满足这三个条件才满足真实长任务门禁；各基线仍完整尝试和保存早停/失败，失败基线不会被强迫继续凑20轮。任务在20轮前完成时如实记录门禁未满足，不加冗余调用。

环境变化题必须独立验证最终revision实际发生、模型实际读取最后快照、所有最终证据/处置与新状态一致、旧完成文件没有重写。环境进展、业务输出、真实模型支持和程序保护分别归因。

本轮只有2个独立任务、每组各一次，不计算泛化准确率或稳定收益，不并入216分母。保留原始请求/响应/事件、每次环境观察与推进、最终文件、来源/代码/JAR哈希和独立重评分回执。真实运行和全部来源审核完成后才能验收CM-E4。

## 5. 执行入口与离线准备

数据文件 `benchmarks/context-memory-live-full-v1.json` 由 `scripts/build-context-memory-live-full.mjs` 生成；构建脚本只用于数据制作，不进入Agent工具或环境推进。环境类构造器只接收公开AgentInput及独立EnvironmentProgram，不能接收Task/Gold。read/write沿用现有工具与确定性副作用门禁，只写preview；验证器只检查公开结构，不返回转换答案或正确处置。

`mvn -B -ntp clean verify -Pcontext-memory-full` 默认执行prepare，输出位置可用 `-Dcontext.memory.full.output=...` 指定不可覆盖的新目录。入口 `ContextMemoryFull` 的mode为prepare/live/audit；audit从封存文件、原始调用、实际工具事件及环境变更重新评分，不信任summary或记录的PASS。live还需独立人工授权与 `CLAWKIT_CONTEXT_MEMORY_FULL_EVALUATION=true`，不能用正式重放开关启动。

main轮计数另要求live-full运行manifest、实际Provider事件中的DEEPSEEK_V4/requestedModel及ACTUAL usage，固定响应的未知供应商或prepare产物不满足。压力门禁要求成功的L2/L3、压缩前达到warning线、压缩后token估计下降。该估计仅证明机制触发，收益只能使用完整任务的实际用量与正确性。

### 2026-10-05 完整写入载荷计数缺口

固定响应在16384窗口完成24份配置和汇总，但旧分析器只计正文，遗漏write工具参数内的主要JSON载荷；8192探针同样未触发压缩。两次压力计数不能用于选择窗口或收益声明。恢复原定16384窗口，任务、公开规则、预算及输出规模不变；补齐正文、推理内容、工具名/ID/参数及消息结构估算后再预检。所有失败合同日志与先前准备产物保留。

### 2026-10-05 最新证据的完整性与归属

完整动态任务的固定响应回归复现了近期工具返回被两处1000字符首尾截断的问题：即便实际read返回完整状态，模型收到的JSON也已损坏。候选移除MessageMasker的Tier0截断与LadderedCompactor保护区截断，最近3个完整交换保留原工具结果；工具输出策略和上下文硬预算继续限制大小。封存原版策略保持原样。超出预算时如实失败，不能用静默损坏结构的方式装入窗口。

最终采证必须同时满足：根任务运行标识、原始工具提议中的status路径、成功执行事件、环境读取记录、晚于最后变更的时间，以及返回字节/实际文件/最后快照的SHA256一致。两次环境推进也须关联同一根任务的实际write路径。不能仅凭callId或一份内容正确的JSON认定模型已读取最新现场。

LiveFullChangingEvidenceTest从一次初始请求出发，以原生读取到的公开规则和状态生成预览，实际完成1→2→3变化及最终21份输出；固定响应不读取gold生成结果。独立重评分检查全部输出、旧完成记录和最终来源，并对哈希、路径、运行标识、revision四种错误关联拒绝资格。此回归只验证执行器和评分器，供应商仍为UNKNOWN，真实main轮计数为0，不能证明模型长期上下文效果或关闭真实长任务门禁。


## 6. 公开规则验收修订 v2（离线交付，真实效果待验证）

第七轮v1的配置域名错误与首次压缩前的动作误判说明，来源保留和结构校验不能替代任务结果验收。新数据版本为 `context-memory-live-full-acceptance-v2`，由 `scripts/build-context-memory-acceptance.mjs` 从冻结v1生成；只增加版本、验收标识和公开说明，两个任务的源数据、环境推进、Gold、评分、顺序、窗口及预算保持原合同。v1文件与全部历史结果保留。两个任务已多次观察，v2属于开发回归，不是新的未观察留出，也不并入216分母。

三组共用 `PUBLIC_WORKFLOW_ACCEPTANCE_V1`。调用方在单次普通ReAct完成入口装配本地只读检查，最多两次纠正续接，沿用全部请求/Token/工具/deadline/权限门禁。默认入口仍使用v1且不装配检查；仅显式选择v2数据才启用，CLI普通任务没有自动获得此项领域验收。

验收实现只接收AgentInput、EnvironmentProgram与隔离工作区，不能接收Task或Gold，也不读取未来revision。配置检查逐项转写公开迁移映射、环境覆盖、null回退和指定汇总；动态检查当前实际快照、最终revision、证据事实、冷却资格、动作优先级及汇总。内部计算期望值用于判等，不生成或写入产物，不将期望值提供给模型。规则文档SHA256绑定已审阅版本，不声称自动理解任意自然语言规则。保护源必须与公开初始字节一致；可变状态除外。每文件最多65536字节、来源最多32份、预览最多24份，拒绝声明路径中的符号链接、非普通文件和越界文件。

拒绝反馈最多8项，只含产物路径、JSON指针、公开规则码和来源引用；总计不超过2048字符，不带正确值、正确动作、Gold判分或隐含权限。检查记录暂存在有界内存，运行结束后由评测装配层保存 `completion-checks.json`；回调本身不写文件、不调用网络或模型。源哈希对应实际检查字节。业务判等覆盖其已声明规则，不证明一般语义正确、Agent实际读取来源或生产可用性。

原独立Gold评分和新鲜度关联保持不变：即便验收放行，仍须满足全部文件正确、真实原生最终采证、行为约束、至少20个实际main响应、有效压力压缩和完整用量合同。机械验收与模型表现分别报告；新版本结果不能仅归因为Context改善。少于20轮完成就如实保留，不填充请求。

离线入口（仓库根目录）：将 `context.memory.full.dataset` 指向 `benchmarks/context-memory-live-full-acceptance-v2.json`，保持 `context.memory.full.mode=prepare` 并指定全新输出目录。prepare不读取密钥、构造网络Provider或产生真实效果数据。新v2通过整仓验证、零网络prepare、来源/加载代码审核和封存audit后，真实运行仍按第3节和 `docs/context-memory-evaluation.md` 单独取得这一轮数据范围与预算授权；旧授权已结束，不能复用。


## 7. 发送预留与输入规划（离线修订）

公开验收 v2 首轮的候选实例实际余额约 3.3 万 Token，仍高于 16384 窗口；普通估算没有据此缩减上下文，但发送前 UTF-8 预留约 4.1 万而拒绝。这是输入规划与既有硬门禁的口径差异，不能通过降低预留、追加额度或把正确文件记成完成解决。

长任务三组共用可选输入规划：使用 ProviderRequestLimitGateway 原有 conservativeReserve，对实际消息及固定工具定义报价，另测空消息的工具/输出/framing 固定预留。只有原请求报价大于真实实例/本 Run 较小余额时，以可用于消息的预留比例将原生消息 Token 估算映射为更小的压缩规划容量；工具 Token、输出和安全余量照常计入。下传的规划容量独立记录，不冒充实际余额，不改真实账本、窗口、输出或请求上限。每次普通 compact 仍只委托原管线一次，不新增补救模型调用。摘要如被原管线选择仍收费并共享原预算，不能免单。

工具/输出/framing 固定预留已无法容纳时，派发前明确预算停止。必要约束、工具调用图和最近来源由原管线保护；缩减后仍不够，原发送硬检查继续拒绝。规划不是实际收费估算或未来请求次数保证，不能把它本身记为成本收益。每次记录真实余额、前后预留、规划容量、是否缩减及结果是否容纳；不记录来源原文或计算业务答案。CLI 默认、旧构造入口、评分器、Gold、原版 Context 和数据保持原合同。

候选 GENERAL 管线收到低于模型窗口的规划容量后，L1 去重若仍超目标，继续原有 L2。对有效工具调用图，按完整 assistant/tool 交换移除较早历史，逐组检查，保护所有 SYSTEM、USER、任务说明来源和最近三个完整交换；未完成/重复 ID 图不在这一分支驱逐。记录 LOW_RUN_BUDGET_COMPLETE_EXCHANGE 范围，精确旧值仍需正常重读。可选锚点沿用既有比例按较小目标容量规划，必要锚点不够时明确失败；不静默删必要约束，不新增摘要请求，正常充足预算和 OPS 路径保持原处理。C1/C2/C3 仅共用入口规划，候选历史移除属于 C3 修订，不能将所有效果归为同一机制。

2026-10-06 零网络回放使用 v2 首轮两个候选的封存末端输入和实际用量，不加载模型或摘要器。只降低规划容量时两项均仍超预留；移除完整交换后配置仍差 105，动态已容纳；按既有比例收缩可选锚点后，两项最终预留为 31836/24666，对应真实余额 32864/34243。保留全部失败尝试及原始输入哈希，这只证明保存载荷能通过原预算口径，不证明任务可以完成、节省实际 Token 或多出若干可用轮次。真实调用前重新冻结并审核数据/源码/加载类；frozen216入口继续旧构造，其元数据注明本规划只在 full-task 启用，不安排新的216实跑。
