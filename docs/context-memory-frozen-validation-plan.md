# CM-E4 冻结验证实施方案

> 2026-10-04。基于两轮开发证据制定；本文件是执行合同。正式执行器与24个留出任务已实现；真实长任务尚待实现，效果运行与验收状态见 TODO。不读取 API 凭据、不构成模型调用授权。实施状态见 TODO。

## 1. 开发结论与候选边界

两轮为同6个开发任务的18实例：首轮2/18完整通过、108请求、191182 Token；修复轮11/18、82请求、155736 Token。候选已修复非用户文字被提升为用户约束、DETERMINISTIC文件动作多余模型复查，以及递归文件搜索漏查根目录。第三项只有离线回归证据，不追认修复轮失败通过。

关键约束在首轮压缩摘要中保留并进入主请求；M2联合Memory/Session提供全部5个已知必要事实。开发证据目前不要求新增检查点或记忆算法，候选保持普通摘要与BM25。正式组别在任何留出模型得分产生前固定。

## 2. 原版与共同运行时

压缩原版来自`benchmarks/baselines/context-memory-context-original-v1/`的41份Context主源码，逐字节验证首次封存哈希。候选包含来源锚点修复，以及2026-10-05新增的完整工具交换保护：AnchorSnapshotPlanner、DefaultContextPipeline、MessageMasker、LadderedCompactor和私有ExchangeLayout；公共类型ABI保持一致；Tokenizer/ContextBudgetAnalyzer共享正确计数实现。原版单独编译、记录JDK/编译参数/JAR哈希；正式装配必须验证加载来源，避免两组实际用了同一模块。

每组共用当前Engine、Provider、四项文件工具、验证模式、预算、提示与评分器。两个早期运行时缺陷因此不混入压缩组之间的差异。原版指历史Context策略，不能称整个旧版本平台。原版与候选均保留真实用户required锚点溢出失败规则。

## 3. 主对照

| Suite | 组别 | 解释 |
| --- | --- | --- |
| 压缩 | C1_ROLLING_SUMMARY | 固定摘要提示、近期完整3轮，常见强基线 |
| 压缩 | C2_FROZEN_ORIGINAL_CONTEXT | 冻结的原版分级压缩与锚点保护 |
| 压缩 | C3_CANDIDATE_CONTEXT | 来源修复后的分级压缩与锚点保护 |
| 记忆 | M0_NO_HISTORY | 无历史下界，未知题另报 |
| 记忆 | M1_FULL_ARCHIVE_READ_GREP | 原始档案与有界读取/搜索，强基线 |
| 记忆 | M2_NATIVE_MEMORY_SESSION | 当前原生提取、历史摘要与BM25，算法未变 |

记忆三组共用候选压缩。没有开发证据要求M3，因此不增加一个同实现的重复组；M2原版与候选记忆算法源码相同，效果问题是它与完整档案的质量/净消耗差异。不得将共享运行时的修复写成长记忆算法提升。关闭压缩Suite跨会话召回；Workspace State与Working Memory设置统一，并保存实际注入内容。

## 4. 留出任务与冻结顺序

每套12个独立任务，各3次，两套共216实例；统计单位为24个任务，重复不扩大独立样本。按家族额外做聚类敏感性分析。题目须在路径、状态组合、任务行为与叙述上与开发任务不同，不能仅替换变量名称。

压缩任务覆盖：指定范围与多文件输出；已完成阶段与剩余现场检查；新决定覆盖旧决定；环境信息与未经确认建议。记忆任务覆盖：表达改写/多来源组合；事实更新/撤销；相似项目/弱关键词干扰；缺答案/模型假设/历史现场状态。每个任务的全部前置资料属于同一统计块。

Agent只接收原始来源、当前请求和有权访问的隔离文件；gold、来源正确性标签、预期动作和验收程序由evaluator持有。禁止预先生成正确答案摘要或将gold写入Memory。必须直接调用生产提取、Session保存/重开和自动召回。

先冻结生产源码与两种Context装配，再实现不同留出数据并做无网络压力/真值隔离预检。只可按预先统一规则调整压力；不得观察留出模型结果后调提示、阈值、组别或题目。失败后修复形成新版本与新轮次，旧分母与失败保留。

## 5. 用量与执行草案

沿用DeepSeek deepseek-v4-flash、temperature=0、reasoning关闭、每请求最多1024输出、零传输重试、cl100k_base、4096评测窗口。窗口是受控测试条件，非供应商原生容量。请求序列按任务/重复平衡交错并冻结随机种子；状态每实例重置。记录所见模型别名和缓存命中，不假定temperature=0保证确定性。

正式轮上限固定为每实例12请求/45000 total Token，整轮2592请求/9720000 Token；单实例180秒、整轮7200秒（2小时）。这些是上限而非预计消耗，尚未取得该轮授权。摄入、Session摘要、压缩、主任务、所有验证/纠错共享额度。工具最多24次提议，整批超限拒绝，未知usage或超保守预留停止整轮。执行器检查任务、重复、组别、上限与两小时时限；启动前再核验封存哈希并按逐轮合同单独确认。

## 6. 结果与复算

主指标为全部gold满足且根任务正常完成；另报输出正确、约束/必需读取、重复完成步骤、未知题不当确认和所有失败类型。文件SHA验证不等于任务正确。

公开全部尝试的完成数、实际请求/input/output/total/cache、摄入一次成本、主任务成本及端到端时间；两组都成功的配对成本另报覆盖率，不能隐藏失败。比较采用任务块配对bootstrap、5000次、固定种子20261004，报告95%区间；重复执行连同任务进入同一个块。另报每个任务3次全成功的计数。样本小时只陈述固定任务集观察，不称普遍准确率。

Java机械复算检查终态、真实工具事件与原始usage；独立第二实现校验用量/分母。来源材料审核须覆盖全部事实、正确出处、更新关系与未知题；审核者身份及是否盲化明确披露。系统路径和来源派生关系都不能自行证明语义支持。

## 7. 独立live-full门禁

另做两种实际本地长任务：有阶段依赖的配置迁移与持续变化证据下的任务续接。三个压缩主对照共享实际工具/环境，每种至少1次，不混入216重放实例。历史必须由真实模型与工具交互形成，所有阶段入账。记录真实main TurnStarted数、压缩次数、目标完成与保护结果；若任务完成但未达20+ Turn，如实记门禁未满足，不追加无意义对话凑轮数。

上限暂不冻结；需在离线合同及压力准备后单独制定。不得复用当前18实例授权或正式留出轮的剩余额度，也不接入私人项目或远程服务器。

## 8. 退出条件

完整保存源码/数据/提示/工具/配置/评分/二进制哈希，全部实例与未运行原因，原始请求和最终文件；独立机械审计与来源审核通过。留出216执行与独立live-full分别验收，结果不支持改善时保留负结论。准备好原版JAR或通过离线测试都不代表完成CM-E4。

## 9. 正式执行器与离线证据

入口为 `ContextMemoryFrozen` / `context-memory-frozen` profile，默认 `prepare`。它单独加载 `benchmarks/context-memory-heldout-v1.json`，开发入口不能误接正式分母。原版41份源码先验证首轮封存哈希，再独立编译；仅私有 `context.impl` 类由原版加载器加载，公共类型和其他模块共用候选运行时。缺失源码、公共接口变化或来源错误都拒绝运行，不静默退回候选。

12个压缩任务的生产首轮边界预检均触发压力并保留近期窗口；12个记忆任务覆盖组合、更新、隔离和未知。多文件任务逐个评分且只允许声明的产物；当前健康必须读取隔离文件，历史版本与当前观测分开标注来源，当前观测不进入“记忆提取保留”分母。题目由本项目自建，没有外部盲测资质；采样历史用于受控压力，不能称真实形成的长任务。

`scripts/analyze-context-memory-frozen.mjs` 从封存数据独立复算 Java 随机顺序、全部216实例分母、原始调用 usage、阶段与缓存账本，校验独立 Java 的文件/工具重评分结果。任务块 bootstrap 保留同任务3次重复，另做4个家族的敏感性分析；未运行时不计算效果区间，缺失真实用量不记零。两组均成功的成本对照附覆盖率，与全部尝试的总账分开。来源语义审核和 `live-full` 门禁仍需另行完成。

```powershell
mvn -o -B -ntp -Pcontext-memory-frozen clean verify '-Dcontext.memory.frozen.output=D:/Agent/miniclaw/tmp/cm-frozen-prepare-new-run'
mvn -o -B -ntp -pl clawkit-evaluation -am -Pcontext-memory-frozen verify '-Dcontext.memory.frozen.mode=audit' '-Dcontext.memory.frozen.output=D:/Agent/miniclaw/tmp/cm-frozen-prepare-new-run'
```

每轮使用全新目录。`live` 入口还要求人类明确授权、`CLAWKIT_CONTEXT_MEMORY_EVALUATION=true` 与密钥；开关不代表授权。准备产物中的216个 `NOT_RUN` 是完整规划分母，不能作为完成或成功实例。

## 2026-10-05 候选刷新

原Engine没有全组共用的always-on mask；遮蔽属于当前Context Pipeline的压力处理路径。原版与候选分别装配其私有Context实现，C1采用独立摘要。此前`cm-frozen-prepare-20261004-03`只准备了216个NOT_RUN实例，未产生模型分数；修复单请求多工具往返后必须保存新的准备、源指纹与审计，旧产物不覆盖。数据、分母和预算不因本次修复调整。

独立live-full见[合同](context-memory-live-full-plan.md)：2个新任务/6实例，空历史、实际文件工具、三版合成环境；与216历史重放采用不同受控窗口和近期交换定义，结果分别报告。全任务预算单独授权。

### 共享计数器例外

2026-10-05核对到正文计数遗漏工具参数。Tokenizer/ContextBudgetAnalyzer的计数实现统一修正，所有组使用同一实现；公开ABI与原版JAR逐项反射核对，其他公共源码仍逐字节核验。原版41份归档不修改，不加载其旧正文计数器。原版组因此定义为“原版私有Context策略＋共同正确计数器/Runtime”，不称完整旧模块执行。估算影响压力/安全判断，收益仍以actual usage和质量为准。
