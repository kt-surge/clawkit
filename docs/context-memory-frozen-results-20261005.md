# 上下文与记忆首轮正式结果（2026-10-05）

## 结论

本轮没有证明候选压缩策略的完成率或成本收益。原生 Memory + Session 能补回无历史组缺失的信息，但任务完成率和全阶段消耗均落后于完整历史检索。结果与全部失败保留；目前不适合把“压缩节省”或“记忆提升准确率”写成简历成果。

## 条件与分母

- 24 个自建合成任务：12 压缩、12 跨会话记忆，各 3 组 × 3 次，共 216 实例；全部尝试，0 未运行。
- 这 24 个任务是统计单位，216 次执行不是 216 个独立任务。压缩任务重放事前冻结的历史，运行类型为 live-continuation。
- 请求 api.deepseek.com / deepseek-v4-flash；响应记录别名 deepseek-flash；temperature=0、reasoning 关闭、传输重试=0。显式评测窗口 4096，输出上限 1024，不代表供应商原生容量。
- 每实例最多 12 请求、45000 Token；整轮最多 2592 请求、9720000 Token。摄入、记忆提取、Session 摘要、压缩、主任务与验证均纳入账本。
- 压缩组共用修正的完整协议计数器和其他 Runtime；原版仅加载封存的私有 Context 策略，不是旧版本全产品对照。

## 信息保留与失败原因

开发者在结果产生后进行非盲事实复核，覆盖 108 个记忆实例；相同陈述按内容哈希复核一次，再引用到各实例的实际发送材料。审核者可见原始事实和评分口径，不能称外部独立盲评。

- M2 可回答的历史事实：提取 51/51 支持，实际模型输入 51/51 支持；M1 实际输入 51/51，M0 为 0/51。
- 新鲜工具事实三个组各 6/6 支持，单独统计，不计入记忆提取保留率。无答案任务不进入事实保留分母。
- 这里衡量必要事实是否出现在提取或实际输入中，未识别完整检索排序；Recall@K、Precision@K 不可评分。
- 压缩组主要停在 COMPACT_FAILED。部分实例第一次 L3 已将历史压到可发送，随后保留区、工具定义、输出预留和锚点再次超出总预算；不能将发送前正确拒绝记作完成，也不能据此断言摘要丢失了事实。
- M2 另有模型把不同项目的召回记录理解为互相矛盾或未经确认，尽管相应项目范围和事实仍在输入中。信息可见和任务完成是两项指标，需要分别修复与验证。

## 独立长任务

另一个从空会话开始的 live-full 轮次含 2 个独立任务 × 3 组，共 6 实例。六个均因输出达到 2048 Token 上限后被 Provider 拒绝而结束；不执行被拒响应内的部分工具调用。

实际 20 请求、76047 Token，包含 6 个付费失败响应；每实例只完成 3–4 个实际主调用，尚未触发压缩压力。因此真实 20+ Turn 门禁未满足，不能借正式重放或固定响应夹具补足。该轮结果见同目录下独立报告与审计。
